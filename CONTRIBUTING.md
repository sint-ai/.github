# Contributing to SINT Labs

Thanks for contributing to SINT. We work best with issues and pull requests that are concrete, reproducible, and tightly scoped.

## Before opening an issue

- Search existing issues and pull requests first.
- Explain the exact repo, feature, or integration involved.
- Include screenshots, logs, or example payloads when relevant.

## Pull request expectations

- Keep changes focused on one problem.
- Explain user impact and testing clearly.
- Avoid unrelated refactors in the same PR.
- Flag risk areas such as auth, agent execution, or external integrations.

## Sensitive topics

If your report involves vulnerabilities, secrets, or private user data, do not file a public issue. Follow [`SECURITY.md`](./SECURITY.md).
